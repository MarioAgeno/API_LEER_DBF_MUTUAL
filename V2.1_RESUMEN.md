## Cambios Realizados en v2.1

### 1. Nuevas Funciones Helper Implementadas

Se agregaron 6 funciones para resolver los `id_sg` de los catálogos de AgilPagos:

#### `get_tipo_persona_id_sg(tipopers)` (línea 83)
- **Fuente:** Tabla UIFPersona.dbf
- **Relación:** socios.TIPOPERS = UIFPersona.id
- **Retorna:** id_sg del tipo de persona

#### `get_actividad_id_sg(actividad)` (línea 106)
- **Fuente:** Tabla Actividad.dbf
- **Relación:** socios.ACTIVIDAD = Actividad.CODIGO
- **Retorna:** id_sg de la actividad económica

#### `get_estado_civil_id_sg(estcivil)` (línea 119)
- **Fuente:** Tabla EstCivil.dbf
- **Relación:** socios.ESTCIVIL = EstCivil.id
- **Retorna:** id_sg del estado civil

#### `get_provincia_id_sg(codpostal)` (línea 132)
- **Fuente:** Tablas horasacr.dbf y provincias.dbf (multi-tabla)
- **Relación Compleja:**
  1. socios.CODPOSTAL → horasacr.CODIGO
  2. horasacr.inaescd → provincias.PROVINCIA
- **Retorna:** id_sg de la provincia
- **Nota:** Esta es la más compleja porque requiere navegar dos tablas

#### `get_pais_id_sg(pais)` (línea 156)
- **Fuente:** Tabla Paises.dbf
- **Relación:** socios.PAIS = Paises.CODIGO
- **Retorna:** id_sg del país

#### `get_situacion_iva_id_sg(sitiva)` (línea 168)
- **Fuente:** Tabla CodIva.dbf
- **Relación:** socios.SITIVA = CodIva.CODIGO
- **Retorna:** id_sg de la situación de IVA

### 3. Nuevo Campo en Respuesta: Datos_Integracion_AgilPagos

**Estructura:**
```json
{
  "Datos_Integracion_AgilPagos": {
    "tipo_persona_id_sg": "string o null",
    "actividad_id_sg": "string o null",
    "estado_civil_id_sg": "string o null",
    "provincia_id_sg": "string o null",
    "pais_id_sg": "string o null",
    "situacion_iva_id_sg": "string o null"
  }
}
```

**Comportamiento:**
- Cada campo es independiente
- Si una tabla no existe → valor null
- Si el valor no se encuentra → valor null
- Si hay error → excepción capturada, valor null
- La consulta continúa aunque falten tablas

## Notas de Implementación

1. **Normalización de IDs**: Todas las funciones usan `normalize_id()` e `ids_match()` para tolerar variaciones en formato

2. **Manejo de Errores**: Patrón consistente try/except en todas las funciones helper

3. **Performance**: Cada consulta carga hasta 9 DBF. Para futuras mejoras se podría implementar caché

4. **Relación Compleja**: La provincia requiere dos lookups (horasacr → provincias), implementado con nested loops

5. **Sin Dependencias Nuevas**: Solo usa dbfread, sin cambios a requirements.txt
